# Подготовка к защите — Liquidity Vault, неделя 08

## Короткие ответы

1. **Что такое Solana?** Блокчейн-сеть, в которой программы обрабатывают транзакции, а состояние хранится в аккаунтах.
2. **Что такое смарт-контракт?** Программа в блокчейне, которая исполняет заранее заданные правила и меняет состояние только через транзакции.
3. **Что такое Liquidity Vault?** В этом учебном проекте — основа хранилища SPL-токенов. На неделе 08 создан только каркас; депозиты появятся позднее.
4. **Что такое Anchor?** Фреймворк для Solana-программ на Rust. Он предоставляет макросы инструкций, сериализацию аккаунтов и проверки account constraints.
5. **Чем программа отличается от аккаунта?** Программа содержит исполняемую логику. Аккаунт хранит данные или токены, а его владелец-программа определяет, кто может менять состояние.
6. **Что такое PDA?** Детерминированный адрес, вычисленный программой из seeds и program ID, не соответствующий обычному приватному ключу.
7. **Что такое seeds и bump?** Seeds — входные байты, определяющие PDA; bump — добавляемый байт, который помогает получить адрес вне кривой Ed25519.
8. **Почему у PDA нет приватного ключа?** PDA специально выводится вне множества обычных ключей. Программа может авторизовать CPI от имени PDA через `invoke_signed` с исходными seeds.
9. **Что такое SPL Token?** Стандарт токенов Solana и его программа, которая управляет mint-ами и token accounts.
10. **Что такое Mint?** Аккаунт Token Program с параметрами токена, включая decimals, supply и полномочия mint/freeze.
11. **Что такое Token Account?** Аккаунт Token Program, который хранит баланс одного mint и внутреннего token authority.
12. **Что такое mint authority?** Полномочие, подпись которого требуется для увеличения supply mint-а.
13. **Что такое token authority?** Поле владельца токенов внутри token account; оно разрешает операции с его балансом.
14. **Что такое share-токен?** В будущих неделях — токен-квитанция о доле пользователя в vault. Сейчас создан только mint с нулевым supply.
15. **Почему share-токен должен выпускать контракт, а не администратор?** Чтобы выпуск происходил по проверяемым правилам протокола и не зависел от произвольной подписи администратора. В этой неделе mint authority назначен PDA программы, но инструкция выпуска ещё отсутствует.
16. **Почему администратор не может просто забрать токены?** Внутренний token authority vault-аккаунта — PDA, а не ключ администратора. В программе также нет инструкции перевода.
17. **Зачем нужна карточка пользователя?** Она связывает адрес пользователя с vault и станет местом учета его депозитов и shares в будущих неделях.
18. **Как найти карточку пользователя?** Вычислить PDA из seeds `["user_card", адрес vault, адрес пользователя]` и program ID.
19. **Чем localnet отличается от devnet?** Localnet — локальный validator для разработки и тестов; devnet — общедоступная тестовая сеть Solana, аккаунты в которой видны через Explorer.
20. **Как проверить аккаунты через Explorer?** Открыть URL `https://explorer.solana.com/address/АДРЕС?cluster=devnet`. Для localnet Explorer не подходит, данные проверяют через RPC или тесты.

## Исходный код

- `programs/liquidity_vault/src/lib.rs`: `initialize_vault` создаёт и заполняет VaultState; `create_user_card` создаёт нулевую карточку.
- `InitializeVault`: `init`, `payer`, seeds и SPL constraints создают состояние, mint и token account; mint authority и token authority задаются PDA VaultState.
- `CreateUserCard`: проверяет PDA vault, требует подпись пользователя и создаёт одну карточку на пару vault/user.
- `VaultState::LEN` и `UserCard::LEN`: размеры сериализованных Anchor-аккаунтов, включая 8-байтовый discriminator.
- `tests/liquidity_vault.ts`: проверки localnet; `scripts/init-devnet.ts`: создание и проверка тестовых аккаунтов в devnet.

PDA seeds:

| PDA | Seeds |
|---|---|
| Vault | `["vault", token_mint]` |
| Share Mint | `["share_mint", token_mint]` |
| Vault Token Account | `["vault_tokens", token_mint]` |
| User Card | `["user_card", vault_state, user]` |

1. **Цель (30 секунд):** «Я подготовил основу Liquidity Vault для Solana. На этой неделе создаются только аккаунты и полномочия; депозитов и выпуска shares пока нет».
2. **Структура (30 секунд):** показать `programs/liquidity_vault/src/lib.rs`, `tests/`, `scripts/`, `Anchor.toml` и конфигурацию проекта в `week-08/`.
3. **Аккаунты и PDA (60 секунд):** объяснить VaultState, Share Mint, Vault Token Account и UserCard; показать seeds. Отдельно различить владельца Solana-аккаунта Token Program и внутренний token authority — Vault PDA.
4. **Инструкции (45 секунд):** показать `initialize_vault` и `create_user_card`; отметить, что подписи и seeds проверяются Anchor, а повторы отклоняются `init`.
5. **Тестирование (45 секунд):** выполнить `anchor test` и показать реальный результат localnet. Пояснить, что тесты проверяют и реальные данные SPL аккаунтов.
6. **Devnet (30–60 секунд):** если деплой подтвержден, показать Program ID и созданные аккаунты в Explorer. Если не подтвержден, прямо сказать об этом и показать подготовленные команды без заявления о публикации.
